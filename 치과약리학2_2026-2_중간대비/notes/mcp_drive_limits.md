# Google Drive MCP 대용량 파일 읽기·내려받기 정리 (2026-10 세션 경험)

규칙 반영 위치: Notion 프롬프트 §3 부칙(대용량 열람 순서), §7 부칙(순차 내려받기·저장 실패).

## 확인된 사실

- `read_file_content`: 텍스트 추출은 파일 크기와 상관없이 성공했습니다. PDF 본문 텍스트는 이 경로가 1순위입니다.
- `download_file_content`(base64): 10MB를 넘는 파일은 실패했고, 10MB 이하여도 환경에 따라 약 6.5MB 이상에서 실패하는 경우가 있었습니다. 같은 환경에서 약 5.8MB까지는 성공했습니다.
- 병렬 내려받기는 하위 에이전트에서 모두 실패했고, Main이 순차로 받으면 성공했습니다. → 병렬 base64 다운로드 금지.
- 큰 도구 결과는 `tool-results` 파일로 저장됩니다. JSON의 `content`가 base64이므로 `python3 -I`로 디코드하세요.
- Claude Code의 MCP 출력 상한은 약 25,000 토큰으로 알려져 있습니다(비공식 자료 기준). 한 번에 읽는 양을 조절하세요.

## 보고할 때

- 실패 사유를 '10MB 초과'로 뭉뚱그리지 말 것. 파일 메타데이터의 실제 크기와 오류 문구(예: "응답 과대")를 그대로 적습니다.
- 못 읽은 파일 목록은 사유와 직접 링크만 간단히. 사용자가 분할·압축해 올린 대체본은 파일명 관례로 찾습니다.

## 권장 순서

1. 메타데이터로 크기 확인 → `read_file_content`로 텍스트부터.
2. 이미지·도판이 필요하면 Main이 순차로 `download_file_content`. 실패하면 사용자에게 분할본(예: "(MCP)" 표기)을 요청.
3. 텍스트만 읽어서는 PDF의 형광펜 정답 표시와 그림을 놓칩니다 → '정답 표시·그림 미확인'으로 기록하고 분할본을 렌더해 확인(§16 부칙).
