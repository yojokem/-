# 정리장 artifact 빌드 구조 (참고)

로컬 빌드 파일은 세션 종료와 함께 유실되었습니다. 이 문서는 구조를 기억하기 위한 기록입니다. 실제 소스는 artifact에서 `read`로 받아 그 위에서 증분 발행하세요.

## 구성

- 단일 HTML(내장 JS 데이터). 탭: 객관식 · 국시 · O/X · Blank·단답 · 서술형 · 내용 정리 · 예상 문제 · 모의고사 · 현황.
- 이미지는 base64를 HTML에 넣지 않고 별도 파일로 발행합니다(`fig19.jpg`, `fig_ksh23·27·30·33·36·38·40.jpg`). 발행 시 Artifact의 `files` 맵을 사용합니다.
- 문항 데이터는 장별 배열(MC23H, MC23~MC31 등)이며 문항마다 `id`, `yr`, `stem`, `opts`, `ans`(1부터 시작하는 보기 번호), `status`(확정·교차확인·추정·추론), `hist`(학번별 출처 번호), `x.expl`, `x.wrong`(보기별 오답 사유), `gap`(근거 한계)을 가집니다.
- 내용 정리 탭: `NOTES[장].secs`(제목·열·행·연결 문항)와 선배 필기 각주 `FN`(CSS 위첨자, 표 행 연결 또는 표 머리 첫 칸).
- 선배 필기(SEN) 처리: 쪽별 판독 `sen_*.json` → 연결 `cmp_*.json`(카드/NT/CH, rel=보강·모순·시험힌트·교안밖, 신뢰도) → 빌드 스크립트 → `data_sen.js`. 신뢰도 상·중만 각주로 쓰고 모순·불확실은 제외.

## 빌드·검증 관례

- 헤드리스 Chromium(Playwright)으로 렌더 후 JS 오류와 가로 넘침을 점검했습니다. poppler(`pdftoppm`, `pdfimages`)와 ImageMagick으로 PDF·도판을 처리했고 PIL과 tesseract는 없었습니다.
- Notion `update_content`는 원자적이고 앵커가 유일해야 합니다. 앵커 개수를 먼저 확인하세요. 이스케이프는 `\~ \{ \} \[ \]`.

## 같은 방식으로 만든 후속 artifact

- 약물별 총정리: 정리장의 내용 정리 데이터를 약물 단위로 재구성한 정적 페이지.
- 23학번 풀이: 정리장 데이터에서 `hist`에 "23학번 Q"가 있는 문항을 번호순으로 추려 퀴즈 UI로 만든 페이지(점수·단원 필터·보기별 해설).
