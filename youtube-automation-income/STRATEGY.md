# 유튜브 쇼츠 자동화 수익화 전략

원본 참고: Threads @short_tuber 게시물 요약 — "캡컷 + 타입캐스트 6만원이면 얼굴/목소리 노출 없이 월 최대 650만원까지 찍었다, 하루 2~3시간이면 된다."

이 문서는 그 주장을 실행 가능한 파이프라인으로 정리한 것이다. **숫자(월 650만원)는 검증되지 않은 개인 주장**이라 목표로 쓰지 않는다 — 다른 계정(채널 8개, 하루 12~17시간, 주7일, 1년 반 운영, 본인 표현 "셀프노동착취")의 실사례를 확인해보니 이 상한선은 하루 2~3시간 단일 채널과는 아예 다른 자릿수의 시간 투입에서 나왔을 가능성이 높다. 그래서 "참고 가능한 상한선"이 아니라 "다른 리그의 사례"로 취급하고, 목표 설정에 더 이상 인용하지 않는다. (이 프로젝트가 그 그라인드 방식을 채택하지 않는 이유와 시간 상한선 원칙은 `CHANNEL_PLAN.md`의 "시간 투입 상한선 원칙" 참고.)

**타겟 확정: 미국(영어권) 시장.** 대본/자막/업로드 메타데이터는 모두 영어로 제작한다. 구체적 니치/소재 기획은 `CHANNEL_PLAN.md`, 소재 사실검증 절차는 `research/RESEARCH_WORKFLOW.md` 참고.

## 1. 핵심 전제

- **얼굴/목소리 비노출**: TTS(타입캐스트) + 스톡/생성 영상·이미지로 편집
- **저비용 툴체인**: 캡컷(무료~유료 저가) + 타입캐스트(TTS, API 무료 티어로 대부분 커버 — `automation/README.md` 참고)
- **시간 투입**: 하루 2~3시간, 즉 완전 자동화가 아니라 "반자동 + 대량 생산" 구조
- **실패 요인**: 대부분 "나중에" 하다가 안 함 → 실행 마찰을 줄이는 게 핵심
- **배포 다각화**: 유튜브에 올리는 것과 같은 대본/영상을 재편집 없이 **TikTok·Instagram Reels에도 동시 업로드**한다. 추가 제작 비용이 거의 없는데(같은 소스 재사용) YPP 문턱과 무관하게 더 일찍 수익/반응이 생길 수 있음 — 지금 당장 시작 가능한 유일한 현실적 다각화 경로로 확인됨

## 2. 채널 설계 체크리스트

1. **니치 선정**: 정보/썰/퀴즈/자기계발/동물/스토리 중 경쟁도 낮고 소재 고갈이 없는 카테고리
2. **포맷 고정**: 도입 후킹 3초 → 본론 → 마지막 반전/CTA. 매 영상 동일 템플릿 사용
3. **채널 아이덴티티**: 제목/썸네일/톤 통일 (얼굴 없이도 브랜드가 되도록)
4. **저작권 리스크 점검**: 스톡 소스, TTS 목소리 라이선스 확인. **배경음악은 캡컷 내장 "무료" 음악 대신 로열티프리 전용 소스(YouTube Audio Library, Pixabay Music 등 상업적 이용 명시된 곳)를 쓴다** — 캡컷 내장 음악이 실제로 유튜브 Content ID에 걸린 사례가 확인됨(직접 검색 확인, 2026-08-25)

## 3. 제작 파이프라인 (하루 2~3시간 기준)

```
[0] 소재 사실검증 (10~15분)
    └ research/RESEARCH_WORKFLOW.md 절차대로 WebSearch로 교차검증 → research/sources_log.csv 기록
[1] 소재/대본 (30분)
    └ 대본 템플릿(templates/shorts_script_template.md) 채우기
[2] TTS 음성 생성 (10분)
    └ 타입캐스트로 대본 → 음성 파일(mp3/wav)
[3] 영상 소스 수집/생성 (30~40분)
    └ 스톡 영상/이미지 또는 AI 생성 영상 클립 확보
[4] 캡컷 편집 (40~60분)
    └ 자막 자동 생성, 컷 편집, 배경음악, 템플릿 적용
[5] 업로드 & 메타데이터 (10분)
    └ 제목/설명/태그/썸네일, 예약 업로드
[6] 업로드 후 확인 (2~3분, 며칠 뒤, 사람이 직접 — §7 역할 분담 참고)
    └ YouTube Studio에서 Content ID 클레임 여부 확인 — 클레임은 영상 단위 문제일 뿐 채널 페널티가 아니므로 과잉대응 불필요, 다만 저작권 스트라이크(3회 누적 시 채널 정지)와는 구분해서 대응
```

캡컷은 공개 자동화 API가 없으므로 4번 편집 단계는 **수작업 유지**가 현실적이다. 1~2번(대본, TTS)과 5번(업로드 메타데이터 작성)은 스크립트로 보조 자동화가 가능하다 → `automation/` 참고. `[0]~[1]`은 매일 하지 않고 주간 배치로 몰아서 처리한다 — `research/RESEARCH_WORKFLOW.md` §6 참고.

## 4. 성장/도달 단계

이 표의 각 단계는 "수익화 단계"가 아니라 "성장/도달 단계"다 — 금전적 기대치는 원칙적으로 0이고, 예외는 손익분기 수준뿐이다.

| 단계 | 조건 | 액션 | 이 단계의 금전 기대치 |
|---|---|---|---|
| 초기 (0~2개월) | 구독자 0 | 매일 1편 업로드(주 5~6일), 유튜브+TikTok/Reels 동시 배포, 포맷 고정, 데이터 쌓기 | 0 |
| 검증 (2~6개월) | 조회수 편차 확인 (구체 기준은 `CHANNEL_PLAN.md`의 20편 재검토 트리거) | 잘 되는 포맷 3개로 압축, 나머지 중단 | 0 |
| 도달 1 (6~12개월) | YPP Tier 1 (구독 500 + 90일 내 쇼츠 300만뷰) 시도 | 팬펀딩/쇼핑 활성화, 손익분기(툴 비용 회수) 목표 | 손익분기 수준 |
| 도달 2 (12개월~, 도달하면 좋음) | YPP Tier 2 (구독 1,000 + 90일 내 쇼츠 1,000만뷰) | 전체 광고수익 + 롱폼 병행 | 광고수익 발생 시작 (확정 목표 아님) |
| 확장 (6개월 이후, 채널 안정화 후) | 채널 안정화 | 세컨 채널/롱폼 확장 + 디지털 상품(전자책·워크북)·뉴스레터 검토. 브랜드딜은 구독 수천 명 이후에나 현실적이라 더 미룸 | 부가 수익 시도 단계 |

업로드 빈도는 "매일 1~2편"이 아니라 "매일 1편(주 5~6일)"로 잡는다 — §3 파이프라인이 하루 2~3시간 예산에 이미 거의 다 차 있어 2편은 물리적으로 안 들어간다. 각 단계 기간도 그라인드 사례(하루 12시간+) 대비 시간당 투입이 훨씬 적다는 걸 반영해 넉넉히 잡았다.

유튜브 파트너 프로그램(YPP) 조건은 실제 검색으로 확인한 수치다: Tier 2(전체 광고수익)는 구독자 1,000명 + 최근 90일 내 쇼츠 조회수 1,000만회, Tier 1(팬펀딩/쇼핑만)은 구독자 500명 + 90일 내 300만회다. 2027-02-01부터 신규 신청자 기준은 더 올라간다(연 8,000시간 시청시간 또는 90일 내 2,000만뷰). (출처: [vidiq.com](https://vidiq.com/blog/post/youtube-partner-program-guide/), [unkoa.com](https://www.unkoa.com/youtube-shorts-monetization-requirements/)) Tier 2를 1년차 확정 목표로 잡는 건 근거가 약해서, Tier 1을 1년차 현실 목표로 두고 Tier 2는 "도달하면 좋음" 정도로 눈높이를 낮췄다.

1년차는 "돈을 버는 해"가 아니라 "다각화된 배포망(유튜브+TikTok/Reels) + 성과 데이터 + Tier 1 문턱 근접"을 만드는 해로 본다. 참고 지표(실사용자 사례 기반 추정치, 확정 약속 아님): 3개월 — 누적 60~80편·데이터 확보 / 6개월 — 구독 300~1,000명 / 12개월 — 구독 1,000~3,000명, Tier 1 시도.

## 5. 가끔 롱폼 병행 전략

- 쇼츠에서 반응 좋았던 소재 3~5개를 묶어 8~15분 롱폼으로 재구성
- 롱폼은 쇼츠 대비 광고 단가가 높고 알고리즘 노출 채널이 다름 → 채널 안정화 이후 월 1~4편 정도로 병행
- 롱폼 스크립트는 쇼츠 대본을 확장하는 방식으로 제작 (완전히 새로 안 씀)

## 6. 리스크와 현실 점검

- 캡컷+타입캐스트 비용은 시작 비용이지, 성공 보장이 아님 — 대부분의 채널은 초반 몇 달간 수익이 거의 없음
- "6,500,000원"은 최대치 사례이며 재현 가능성 낮음. 현실적 목표는 6~12개월 내 손익분기(툴 비용+시간 회수) 정도로 잡는 것을 권장
- 플랫폼 정책 변화(쇼츠 수익 배분율 등) 리스크 상시 확인 필요. **AI 생성 콘텐츠 공개(disclosure) 의무는 직접 확인 결과 현재 이 채널(TTS 내레이션 + 스톡/추상 일러스트, 실존 인물 미등장)은 대상이 아니다** — 공개 의무는 "실존 인물이 하지 않은 말/행동을 한 것처럼 보이거나 사실적인 장면을 생성"하는 경우에만 트리거된다. 향후 사실적인 AI 생성 인물 영상을 스톡 대신 쓰게 되면 그 순간부터 재검토
- 유튜브 의료정보 정책은 구체적 진단/치료 주장에만 적용돼 일반 심리학 팩트는 저위험이지만, 필러4(뇌과학)에서 특정 질환·진단명을 다룰 땐 출처(APA·학술지)를 명시하고 "치료" 단정 표현을 피한다
- 반면교사(타 계정 사례): 소재 수집 후 대본·편집을 통째로 외주화했더니 톤/품질이 무너져 조회율이 급락한 사례가 있음 → 사실검증·톤 관리는 계속 직접(에이전트) 담당하고, 아직 과금 여력이 크지 않으니 유료 트렌드분석 툴(ViewMine 등) 같은 외부 결제 도구도 당장은 도입하지 않는다
- 번아웃/그라인드 압박: 시간 상한선 원칙 상세는 `CHANNEL_PLAN.md`의 "시간 투입 상한선 원칙" 참고 — 상한선을 넘겨야만 결과가 나올 것 같은 압박이 느껴지면 그건 "포맷 조정" 신호이지 "시간을 늘릴" 신호가 아니다

## 7. 역할 분담 (에이전트 vs 사람)

저작권처럼 법적 책임이 걸리거나 오탐/누락의 대가가 큰 판단은 자동화·에이전트 보조에만 맡기지 않고 **사람이 최종 확인/실행하는 항목으로 명시적으로 분리**한다.

| 항목 | 에이전트가 하는 것 | 사람이 직접 해야 하는 것 |
|---|---|---|
| 배경음악/스톡 라이선스 | 로열티프리 소스 후보 안내(YouTube Audio Library 등) | 실제로 그 곡/클립의 라이선스 조건을 클릭해서 확인하고 최종 선택 |
| Content ID 클레임 | 대응 절차·심각도 구분 안내 | 실제 클레임 발생 시 YouTube Studio에서 직접 확인하고 이의제기 여부 판단 |
| AI 콘텐츠 공개 의무 | 현재 정책 기준 판단 근거 제공 | 콘텐츠 형식이 바뀔 때(예: 사실적 AI 인물 영상 도입) 정책 재적용 여부를 직접 재확인 |
| 의료/건강 정보 표현 | 위험 표현 가이드라인 제시 | 필러4 대본에서 실제 진단명/치료 언급이 들어갔는지 최종 검토 |
| 세금/사업자등록 | 일반적 방향·트리거 시점 안내(세무 자문 아님) | 실제 등록·신고는 본인이 직접, 필요 시 세무사 상담 |

**콘텐츠 기획(소재 선정/대본)은 반대 방향으로 나눈다** — 여기는 사람이 초안을 만들고 에이전트가 검증/감수한다: 사람이 소재를 고르고 대본 초안을 쓰면(마케팅·배포·데이터 분석은 안 해도 됨), 에이전트가 WebSearch 기반 사실검증·구조/톤 감수를 맡는다. 절차는 `research/RESEARCH_WORKFLOW.md` §8 참고.

에이전트는 "확인해야 할 지점"과 "왜 확인해야 하는지"까지는 정리하지만, 법적 판단이 걸리는 마지막 클릭/서명/신고는 항상 사람이 한다.
