# 리서치 워크플로우

콘텐츠(팩트/심리학 소재)를 쓰기 전 사실관계를 검증하는 절차. 매 에피소드마다 아래 순서를 따른다.

필러별로 어디부터 검색을 시작할지는 `SOURCE_DIRECTORY.md`(등급별 출처 목록)를 먼저 참고한다.

## 1. 검색 절차

1. `content_calendar.csv`의 topic으로 1차 검색 (예: `"<claim>" psychology study`)
2. 1차 결과에서 **1차 출처(원 연구/학자명)**가 나오면 그 이름으로 재검색 (예: `John Cacioppo negativity bias study`)
3. 최소 2개 이상 독립된 출처가 같은 주장을 하는지 교차 확인
4. 학술 원문을 못 찾으면 "정설로 널리 인용되는 수준"인지 명시하고 과장된 수치(예: "20년간 기억", "30일 만에 잊음")는 대본에서 제외하거나 "속설로 알려져 있다" 식으로 톤 낮추기

## 2. 신뢰도 등급

- **A (원 연구/논문 확인)**: 저자·연구명·연도 명시 가능
- **B (신뢰할 만한 매체가 여러 곳에서 인용)**: Psychology Today, 대학 기관 페이지 등
- **C (출처 불명확/블로그성)**: 대본에 쓰지 않거나 "일부에서는 ~라고 말한다" 수준으로만 사용

## 3. 기록 규칙

검증 결과는 `sources_log.csv`에 에피소드별로 기록한다. 컬럼:

- `ep_no`: 에피소드 번호
- `claim`: 대본에 쓸 핵심 주장 (한 줄)
- `grade`: A/B/C
- `primary_source`: 연구자/기관명 (있으면)
- `url`: 참고 링크 (가장 신뢰도 높은 1~2개)
- `caveat`: 과장/왜곡 주의사항 (있으면)

## 4. 검색 도구

- 세션 내에서는 WebSearch 툴로 위 절차를 수행한다 (에이전트가 직접 실행)
- 자동화 스크립트(`automation/`)에는 검색 기능을 넣지 않음 — 사실관계 검증은 사람/에이전트 판단이 필요한 단계라 자동화 대상에서 제외
- 매 에피소드 제작 전 이 문서의 절차를 거쳤는지 `content_calendar.csv`에 `researched` 컬럼으로 체크

## 5. 흔한 함정

- 바이럴 블로그/유튜브 요약본이 원 연구를 왜곡해서 전파한 수치(예: "20년/30일" 같은 구체적이지만 출처 불명 수치) — 이런 건 신뢰도 C로 강등
- "연구에 따르면" 식으로만 쓰고 정작 어떤 연구인지 못 찾으면 그 주장 자체를 폐기하거나 톤을 낮춰서 사용

## 6. 주간 배치 루틴 (하루 2~3시간 예산 내 지속가능성 확보)

매일 검증+대본을 직렬로 하면 하루 예산의 25~35%를 이 두 단계가 먹는다. 대신 주기를 분리한다:

- **일요일 40~50분**: 다음 1주(5~6편) 소재를 한 번에 사실검증 → `sources_log.csv`, `research/concept_log.csv` 갱신, `content_calendar.csv`의 `researched`를 일괄 `yes`로. 같은 필러끼리 몰아서 검증하면 같은 1차 출처를 반복 조회하게 되어 시간이 절약된다.
  - **필러3(생산성/습관)은 주간 배치에 1편 이하만** — 검증 실패율이 높아 배치 전체가 밀릴 수 있음 (`SOURCE_DIRECTORY.md` 참고).
- **다른 요일(예: 월요일 저녁) 60~75분**: 검증된 5~6편의 대본을 몰아서 작성. `templates/hook_library.md`의 필러별 골격을 활용하면 편당 20분 이내로 단축 가능.
- **평일 제작일**: TTS~업로드(2~3단계, 90~120분)만 남으므로 하루 2~3시간 예산에 안정적으로 들어간다.
- **출처 재순회 주기** (필러별 소스 두께 차이 반영, `SOURCE_DIRECTORY.md` 근거): 필러4(뇌과학) 격주, 필러1·2(인지편향/관계) 월 1회, 필러3(생산성/습관) 월 1회이되 신규 발굴보다 기존 A급 소재 재확인에 무게. 이 재순회는 매달 첫째 주 일요일 배치에 15~20분 얹어서 처리(별도 세션 만들지 않음).
- **성과 기록**: `templates/performance_log.csv`(조회수/시청지속률/필러 등)를 업로드 시작(ep01)부터 채운다 — 20편 재검토 트리거(`CHANNEL_PLAN.md`)를 판단하려면 편별·필러별 데이터가 미리 쌓여있어야 하므로 소급 기록하지 말고 처음부터 매주 기록. 갱신도 일요일 배치에 얹어서 처리(업로드 후 7일 지표 기준).

## 7. 소재 중복 방지

`research/concept_log.csv`에 사용한 개념(`concept_key`, 예: `negativity_bias`)을 기록해 21편 이후 소재를 뽑을 때마다 대조한다. 완전 금지가 아니라 "같은 개념을 다른 각도로 재사용했는지"를 추적하는 용도 — `angle` 컬럼에 그때 다룬 관점을 짧게 남긴다.

## 8. 콘텐츠 감수 절차 (사람 초안 → 에이전트 검증)

콘텐츠 기획(소재 선정·대본 작성)은 사람이 초안을 만들고, 에이전트가 아래 4가지를 검증해 짧게 피드백한다. 사람은 마케팅/배포/데이터분석을 몰라도 되고, 판단이 어려운 부분(사실관계, 톤 일치, 중복, 정책 리스크)만 에이전트가 대신 확인한다.

사람이 소재나 대본 초안을 던지면 에이전트는:

1. **사실검증**: WebSearch로 §1 절차대로 교차확인 → 등급(A/B/C) 매기고 `sources_log.csv`에 기록. C급이거나 출처 불명 수치가 있으면 구체적으로 지적하고 대체 표현 제안
2. **중복 확인**: `concept_log.csv` 대조 → 이미 다룬 개념이면 각도가 충분히 다른지 판단
3. **구조/톤 체크**: `templates/hook_library.md`의 훅 패턴에 맞는지, `CHANNEL_PLAN.md`의 톤(차분하고 권위 있는 내레이션)과 어긋나지 않는지, 길이가 30~59초 분량에 맞는지
4. **정책 리스크**: 필러4(뇌과학) 소재에서 진단명/치료 단정 표현이 들어갔으면 STRATEGY.md §7 기준으로 짚어줌(최종 판단은 사람)
5. **오리지널 통찰 확인**: 대본에 사람이 직접 쓴 관점/코멘트가 최소 한 줄 있는지 확인 (STRATEGY.md §6·§7의 "비authentic 콘텐츠" 정책 대응 — 없으면 업로드 전 필수 보완 항목으로 지적)

피드백은 "이대로 써도 됨" / "이 부분만 고치면 됨" / "이 소재는 재검토 필요" 셋 중 하나로 명확하게 끝맺는다 — 판단을 사람에게 되던지지 않는다. 단, 5번(오리지널 통찰)이 빠진 경우엔 "이 부분만 고치면 됨"으로 분류하되 이 항목만은 에이전트가 대신 채우지 않는다.
